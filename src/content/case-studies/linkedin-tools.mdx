<CaseSection title="I built a command-line toolkit where every external action leaves evidence">
  I built a Bun and TypeScript toolkit for LinkedIn analytics, job capture, and read-only Sales Navigator research, with guarded outreach and a local review queue.

    The opening screenshot shows the original Python review interface.

    Browser automation is easy to demo and hard to trust. I needed to know what each workflow was allowed to do, what evidence supported each step, and how to check the result when the browser left an outcome uncertain.

</CaseSection>

<CaseSection title="Outreach waits for review and a receipt">
  LinkedIn Tools is a public project that brings job capture, hiring-team research, draft outreach, and follow-up handoffs into one system.

    A SvelteKit review queue groups hiring-team leads by person, so each contact has one reviewable draft, and it records approval before the send path can run.

</CaseSection>

<CaseSection title="Each step has an owner and leaves a record">
  <DecisionBlock title="Capture jobs in phases.">
    Chrome capture stages pages in SQLite. Normalization then deduplicates by LinkedIn job ID, one page per transaction, and short resumable runs stay within a wall-clock budget so an interrupted run can pick up where it stopped.
  </DecisionBlock>

    <DecisionBlock title="Triage with evidence, not rejection.">
    Every kept job with hiring-team contacts gets a strong, possible, or weak bucket with the evidence behind it. Triage never rejects a job or changes its review status.
    </DecisionBlock>

    <DecisionBlock title="Hand work to other systems through packets.">
    Deterministic packets describe the next draft, application, HubSpot, Instantly, or follow-up step. Follow-up tasks are scheduled 5, 8, and 12 days after the first message, stop when a reply arrives, and skip any follow-up that already has a receipt.
    </DecisionBlock>

</CaseSection>

<CaseSection title="Research stays read-only">
  Sales Navigator account capture works through caller-owned Chrome tabs and stores bounded evidence through the command line. It reads accounts and saved searches and never sends, connects, or edits anything.

    A weekly seven-day content analytics export and the job checks run through Playwriter, while job capture, enrichment, and Sales Navigator research use caller-owned Chrome tabs.

</CaseSection>

<CaseSection title="The same pattern applies beyond LinkedIn">
  This is how I would shape the same workflow inside a company once spreadsheets, chat threads, and ad hoc scripts start to break down.

    I would give each action an owner, store the workflow state, require approval for irreversible actions, and capture enough evidence to make the next step visible. Automation can then continue only when the system can explain what happened.

</CaseSection>
